# 网页生图技术附录

版本：v1.3
更新时间：2026-09-13
适用范围：通过 Chrome Computer Use extension，在用户已登录的 ChatGPT 网页中生成或编辑图片。

本文件只记录易变化的网页操作与模型名称核验方法。故事策划、角色设定、连续性、拼接和验收仍以《温蒂日常小红书漫画工作指引》为准。

## 一、默认渠道与焦点边界

- 正式生图的生产传输标记为 `direct-chrome`，使用 Chrome extension 的新建专用标签页，不直接调用 Codex `imagegen` 服务，也不使用 Codex 内嵌浏览器 IAB。
- 每个请求只新建一个 **🎨 温蒂生图** `sessionName` 标签页，并由返回的 tab 绑定后续 Playwright 操作；`createBrowserTab` 不传 `visible`，不接管、导航或写入已有的温蒂创作室标签页，完成或失败后关闭自有 tab。
- 当前公开 Computer Use API 没有窗口或标签页 active/focused 设置、恢复或校验接口。创建专用标签页时 Chrome 可能短暂取得焦点，无法严格保证零焦点切换；不得声称后台隐藏或焦点已经恢复。整个流程不使用坐标、系统鼠标、系统键盘、脆弱快捷键或私有 API。
- 若 Chrome 报告焦点、浏览器或上传能力错误，在上传和发送前停止并保留记录；不会退回 IAB 或其他标签页重试。已有工作室标签页的内容保持不变。

## 二、当前 direct-chrome 流程

以下是当前生产约束；本次只做本地代码和夹具回归，不把本地通过表述成真实网页生成：

1. 先核对当前 `requestId`、授权记录和执行清单，再调用 `cua.createBrowserTab("chrome","https://chatgpt.com",{sessionName:"🎨 温蒂生图"})`。不传 `visible`，只保留这个新建 tab。
2. 等待页面完成加载，切换到“聊天”并确认已登录；上传参考图时只用该 tab 的 Playwright `waitForEvent("filechooser")` 和 `chooser.setFiles()`，每张都确认出现独立附件。
3. 附件齐全后再一次性提交冻结的单分镜提示词。逐张说明其角色：身份参考、环境参考、物件参考或待编辑原图。
4. 页面显示“正在生成图片”或同等状态时等待完成，禁止重复提交。
5. 页面显示“已生成图片”后，先检查可见结果，再获取当前页面加载的原始 PNG；网页截图不能代替原始成稿。
6. 原图立即保存到本篇 `素材/` 并使用语义化版本名。若原图不是1080×1440但宽高比正确，保留原图，再无拉伸导出1080×1440 RGB PNG发布版。
7. 清单写入 `downloaded` 后调用该 tab 的 `close()`；失败时也关闭自有 tab，保留错误、提交状态和请求身份，不自动重发。

### 历史 IAB 验证记录（仅供追溯）

以下流程于2026-08-16在用户已登录的 ChatGPT 网页中跑通；它记录的是旧的 Codex 内嵌浏览器路径，不是当前生产入口：

1. 使用客户端内嵌浏览器打开 `https://chatgpt.com/`，确认账号已登录并进入本篇已有会话或新会话。
2. 上传参考图时，优先按顺序把本地图片写入内嵌浏览器剪贴板，再在输入框逐张粘贴；每张都要确认出现独立附件。
3. 附件齐全后再一次性提交冻结的单分镜提示词，等待生成并获取原始 PNG。
4. 原图立即保存到本篇 `素材/` 并使用语义化版本名；修正版使用 `-v2`、`-v3` 等版本名，不覆盖当前修改依据。

## 三、提交与恢复规则

- 每次网页提交只解决一个明确分镜或一项明确修改。
- 提示词必须包含页码或用途、目标比例、固定设定、附件角色、允许文字和禁止项。
- 局部修改必须把用户本次说明作为独立 delta，与冻结原始 prompt 和明确选定的编辑基图一起提交；连续失败不得自动串联失败稿。只涉及文字或排版的问题走本地 reletter/recompose，不重新调用远端生图。
- 本地已压缩且源文件 SHA-256 未变化的附件可以直接复用，不重复打开或分析；执行记录需保留复用数量、准备耗时和上传前后的字节数。
- 网页超时或状态异常时，先检查会话、网页图片资源和目标 `素材/` 目录是否已经产出文件，再决定是否重试；发送状态未知时不得自动重发。
- 用户指出单点问题后，优先从当前图片的“编辑”入口继续；写清“只改变什么”和“必须保持什么”，修正版仍重新检查人物、肢体、文字、主题和尺寸。

## 四、图像模型名称核验

- 页面显示的聊天模型名称不等于底层图像模型名称。
- 浏览器网页执行器是机械执行角色，使用当前创作模型的 `low` 思考力度；方案规划保留用户选择，画面校对独立使用 QA 角色。`request.json`、`web-generation.json`、任务和作品统计必须同时记录 creative/browser-executor/QA 的模型、思考力度与阶段时间。`accepted` 仅表示执行器已接单，不能当作 `submitted`。
- 产品名称与API模型标识必须分开表述；只有页面详情、生成记录或官方可核验证据直接暴露具体图像模型时，才能报告“已确认”。
- 图片尺寸、画风、速度或聊天模型名称均不能作为底层图像模型版本的证据。
- 页面和下载文件未暴露模型元数据时，应写：“本次通过 ChatGPT 网页图片生成功能完成，但具体底层图像模型未由页面披露。”
- 具体产品名称、开放范围和模型映射可能变化；需要对外确认时重新查阅当时的OpenAI官方说明，不在核心工作指引中长期固定版本结论。

## 五、技术附录维护

- 网页按钮名称、上传方式、下载能力或模型披露方式变化时，只更新本文件，不修改世界观。
- 更新后记录验证日期；未经实际跑通的替代流程不得标记为“已验证”。

## 六、温蒂创作室后台接入（2026-09-13）

温蒂创作室的新图片任务统一登记为 `transport=direct-chrome`、`browser=chrome`，并由一次独立的 Codex `exec` 使用 `browserMode=chrome` 驱动 Chrome extension。`provider=chatgpt-web-iab` 仅作为旧作品记录的持久标识，新的请求不使用 IAB，也不会在失败后退回 IAB；不得接管或导航已有 studio tab。

公开 CUA 当前报告 `focusRestoration=unsupported`、`focusSafe=false`：创建专用 tab 可能短暂取得 Chrome 焦点，但后续只操作返回的自有 tab，成功或失败都关闭它。该边界不能严格保证零焦点切换，清单、界面和报告必须如实保留，不能写成“后台隐藏”或“焦点已恢复”。

每个作业以 `web-generation.json` 为事实来源：

```text
queued → ready → submitted → downloaded
                    └────────→ failed
ready 之前失败：submitted=false，可确认未提交
submitted 之后失败：submitted=true，结果未知，不自动重生
```

网页动作必须在同一个 Codex 回合内完成附件上传、唯一一次发送、等待和下载；不能在 `ready` 后退出等待确认。用户在创作室中的确认动作通过 `worker-request.json.authorization` 持久化，后台不得重复询问。

原图优先通过页面下载事件取得，并以图像解码、尺寸、格式和 SHA-256 校验。截图、缩略图和程序重绘都不能代替原图。

2026-09-09 的历史记录曾用两张温蒂人设完成一次真实单格验证：唯一网页请求成功，原始 1497×1051 RGB PNG 已落盘并挂接，清单包含真实会话 URL、`submitted=true` 与 `state=downloaded`。该记录属于旧路径，不证明当前 direct-chrome 运行；后续局部编辑仍可复用图片记录中的 `conversationUrl`，不可据此自动重发。
