# 生图工作流稳定性优化实施方案

日期：2026-09-07  
项目：温蒂创作室  
用途：分阶段实施与验收记录。本轮已完成第一批（失败状态/恢复入口、可靠落盘与有限幂等）；未部署常驻 Worker，也未发起真实生图请求。

## 一、结论与范围

采用任务持久化、原图恢复、独立执行的方向，优先解决失败误判、恢复入口失效和重复生成。架构改进不能直接消除 Worker 到远端生图服务的网络故障。

本轮实际交付：为每次图片尝试保存 `request.json`、已有 `events.jsonl`/`response.txt` 和 `result.json`；仅在候选原图唯一时自动认领；以临时文件校验、哈希和原子改名保存原图；增加“只重新校对已保存原图”入口；明确重试以持久防重复标识去重。未把结果未知自动升级为“没有图片”。

不引入 GPT Image 2 API 或其他生图渠道，不修改已确认的漫画方案、人设与素材。保留完整方案和样张确认门槛。

方案依据：用户提供的《Codex Imagen 生图工作流稳定性优化方案》全文，以及本次对项目代码和本地 CLI 帮助的只读检查。参考分享页：https://chatgpt.com/s/t_6a9e5a51da3481918fb6d86ea214f0b2

## 二、已有能力与建议修正

项目已经具备单张生成、后台异步执行、每 2.2 秒短轮询、独立制作记录、错误后的原图找回和 JSON 原子写入。应补足缺口，不重复建设。

| 原建议 | 本项目处理方式 |
| --- | --- |
| 优先添加 `--no-stream` | 当前调用官方 `codex exec`，不是示例 `codex-imagen.mjs`；已检查的 CLI 帮助没有该参数，不直接添加。 |
| 非流式可避免长连接问题 | 非流式仍可能一直等待服务端完成，不天然支持断线恢复。 |
| 短轮询彻底取消长连接依赖 | 只能解耦页面与本地任务；Worker 到远端生图服务的连接仍存在。 |
| 本地没有图片就重试 | 没有本地图片不能证明远端未生成，结果未知时不自动重试。 |
| 只使用四种状态 | 必须区分结果未知、原图已保存和等待校对。 |
| 图片必须大于 50 KB | 不设硬性大小门槛，以完整解码、尺寸和任务归属为准。 |
| Worker 常驻后节点断开也能继续 | 本地进程可以存活，但远端请求仍可能失败。 |
| 扩展多个 Provider | 暂缓，本次只修复既有链路。 |

## 三、第一阶段：统一失败状态与恢复入口

修改文件：`server/engine.mjs`、`server/server.mjs`、`app/page.tsx`。已完成。

统一任务状态：

```text
queued → running → artifact_saved → completed
             ├→ failed_no_output
             └→ unknown_result
```

额度不足、用户暂停作为独立暂停原因保存，不覆盖任务原始结果。校对状态独立记录。

实施内容：

1. 前后端使用统一的能否找回、能否重试、能否继续判断。
2. 修复 `currentTask=failed_no_output` 而 `pending`、`lastFailure` 为空时，前端允许重试、后端拒绝的问题。
3. “重试这一张”只处理当前图片，完成后暂停，不自动推进整篇。
4. 原图已保存但校对失败时，只重做校对。
5. 刷新额度提示时保留之前的网络错误记录。
6. 对旧任务做兼容迁移；不因模型口头说明直接把历史不明结果升级为确定无图。

验收：失败后显示有效的下一步；接口和页面状态一致；校对失败不触发重复生图。已由隔离夹具覆盖“原图仅重新校对、不增加 image 任务”。

## 四、第二阶段：可靠落盘与结果核对

修改文件：`server/bridge.mjs`、`server/engine.mjs`。复用现有 `.制作记录` 目录。已完成核心落盘与归属判断；暂不新增候选图选择 UI。

每次尝试保存：

```text
request.json       任务输入、版本、参考图摘要
events.jsonl       原始执行事件与错误
response.txt       最终回复
result.json        图片路径、摘要、校验结果
```

处理顺序：

1. 启动前保存任务清单和准确输出路径。
2. 正常退出、异常退出、超时、用户暂停均进入结果核对；停止后先核对产物，再决定终态。
3. 只检查当前任务目标文件和对应线程产物，不扫描无关任务的图片来认领结果。
4. 确认文件写入完成，完整解码图片，检查尺寸、格式及任务归属。
5. 经临时文件复制并原子改名后，登记 `artifact_saved`。
6. 最后执行画面校对。图片保存和视觉验收分别记录。

风险修正：

- 多个候选图片归属不明确时，保留待核对，不能按最新时间随意选图。
- 删除提示词中“网络错误后直接声明没有产出”的强制要求。
- 网络错误加模型口头说明不足以证明远端未生成；确定无图必须有相应证据，否则保留 `unknown_result`。
- 日志保留错误分类和任务关联，不记录令牌、认证头或其他凭据。

验收：有效图片已落盘但进程非零退出、最终回复丢失或校对超时，仍可恢复；损坏文件和其他任务图片不会误判成功。已覆盖自动校对传输失败和同一线程多候选图不自动认领；真实远端异常仍待用户授权的单图验证。

## 五、第三阶段：幂等与有限重试

增加持久化操作 ID 与尝试记录：已完成明确“重新生成这一张”的防重复记录，以及既有样张决定防重复记录；其他写操作仍由页面禁用和服务端活动任务锁保护，后续队列阶段再统一为命令存储。

- 同一次操作重复提交返回原任务，不新建生图请求。
- 页面未收到受理响应时查询原任务，而不是重新发起生成。
- 用户明确重试时创建新尝试编号，保留旧记录。
- 输入记录作品版本、分镜位置、提示词摘要、参考图内容摘要和编辑目标摘要。
- 同一任务已有有效原图时直接复用；内容摘要不能阻止用户明确要求的新版本生成。

| 情况 | 行为 |
| --- | --- |
| 状态查询失败 | 自动退避后再查询。 |
| 已生成，复制或登记失败 | 重试本地保存。 |
| 已有原图，校对失败 | 只重试校对。 |
| 明确未提交或明确拒绝 | 根据错误类型处理，不盲目重试。 |
| 提交后连接中断且无本地图 | 标记结果未知，先找回；新生成由用户确认。 |

验收：双击、刷新、请求重发不会重复启动生图。本地幂等不等于远端严格只生成一次，不作此承诺。

## 六、第四阶段：持久化单任务队列

新增文件：`server/job-store.mjs`。使用 JSON 文件与目录锁，复用原子写入能力，不引入 Redis、RabbitMQ 或 Kafka。已完成。

实施内容：

1. 任务持久化成功后才向页面返回任务 ID。
2. 全局生图并发为 1，不仅限制同一作品。
3. 执行前核对方案确认状态、版本和额度。
4. 保存领取者、开始时间、心跳和尝试编号。
5. 重启后可恢复未开始任务；执行中的遗留任务先核对进程和产物。
6. 心跳过期不等于执行者已退出，不能据此直接再次生图。
7. 任务领取使用单执行者约束或可靠互斥；单纯原子改名并不自动保证跨进程领取互斥。

验收：多个作品提交不会绕过并发限制；进程异常退出后记录完整；恢复不重复生成。已通过隔离回归验证两个不同作品严格串行，且任务写入完成状态与心跳。

## 七、第五阶段：独立 Worker 与 Mac 生命周期（待单独部署）

新增建议文件：`server/image-worker.mjs`。调整 `launch.mjs` 和服务关闭流程。

职责：

- Web 服务负责提交操作、查询状态和展示结果。
- Worker 负责领取任务、调用 CLI、核对图片和保存执行结果。
- 同一任务执行状态由 Worker 单独写入；Web 服务通过命令提交暂停等操作，避免双方覆盖状态。

Mac 常驻采用用户级 LaunchAgent，通常在用户登录后启动。外置硬盘未挂载时等待并退避，不在错误位置新建作品目录。

再次点击 App 可以替换网页服务，但不终止 Worker。主动暂停时停止领取新任务，并核对当前任务结果。记录实际 CLI 路径及网络配置来源，不写死代理端口，不记录认证秘密。

验收：关闭浏览器、重启网页后台不影响已启动任务；重复打开 App 不产生多个 Worker；外置硬盘缺失时不会错写数据。

## 八、第六阶段：查询优化与真实链路验证

保留短轮询，上一次请求结束后再安排下一次，避免慢请求重叠。连接失败时退避，恢复后继续查询原任务；查询超时不能改变生图任务状态。页面轮询已完成上述实现，并按项目 revision 忽略晚到的旧响应。

超时不直接照搬 300 秒：分别记录 CLI 启动、远端调用、原图保存和校对耗时，再确定各阶段阈值。超时后仍需结果核对，不能自动视为确定无图。

先用模拟 CLI 覆盖：

- 非零退出但已有有效图片。
- 半张图片、错误文件、多候选图片。
- 图片已保存但状态尚未登记时崩溃。
- 重复点击、重复提交、服务重启恢复。
- 额度暂停与图片失败同时存在。
- 校对失败只重试校对。
- Worker 重复启动、外置硬盘缺失。

结合现有 `tests/workflow.test.mjs` 和 `tests/launcher.test.mjs` 增加对应回归用例，必要时新增任务队列测试。完成适用测试和构建检查；不要把局部检查描述为全项目通过。

模拟验证通过后，有限测试无参考图与带参考图的真实请求，记录网络路径、耗时、错误和有效产物。普通 HTTPS 200 不作为生图成功证据。真实生图、服务安装及重启留待用户授权 Terra 实施时执行。

## 九、交付顺序与回退

第一批：第一至三阶段，修复当前恢复错误、补齐产物核对和幂等。代码与隔离测试已完成；真实网络链路验证须单独取得用户授权。

第二批：持久化队列与查询优化已完成。独立 Worker 与用户级 LaunchAgent 仍需单独部署和真实生图验证，不能仅凭源码或普通 HTTPS 判定为完成。

实施前保留作品状态和原始素材备份。状态迁移可重复执行，不删除历史任务与图片。Worker 上线前验证旧执行入口已停止领取任务；回退时先确认没有活动生成，再恢复旧入口，防止双执行者。

最终完成标准：图片有效落盘、失败可恢复、重复操作不重复生成、重启不丢失任务；网络错误能独立定位。暂不增加其他 Provider，不添加未经确认支持的 `--no-stream` 参数。

本轮验证：`npm test` 20/20 通过；`npm run build` 通过并完成本机预渲染；`git diff --check` 无格式错误。以上为本地模拟 CLI 与回环服务验证，不等同于真实远端生图链路成功。
