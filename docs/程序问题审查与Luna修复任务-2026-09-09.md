## 3. P1-01：分镜更新后导出旧页面

### 触发与证据

1. 一页漫画已生成并通过校对。
2. 用户修改其中一个分镜。
3. 新图保存成功，但随后的模型校对中断。
4. 用户重新校对原图，再点击继续制作。
5. 系统恢复到 `ready`，仍保留旧页面，且可以验收导出为 `complete`。

隔离复现结果：

```text
REVISION_QA_INTERRUPTED:
  status=attention, newPanel=true, oldPageRetained=true,
  pageQA=true, storyQA=true
AFTER_REVIEW_AND_RESUME:
  status=ready, stillOldPage=true, panelChanged=true
STALE_PAGE_EXPORTED:
  status=complete, exportMatchesOldPage=true
```

### 原因与代码入口

- `server/engine.mjs`：`generate()` 约第 395–396 行在校对之前调用 `attachImageRecord()`，新分镜已经成为当前图。
- `reviseImage()` 约第 537–540 行在 `await generate()` 返回后才移除旧页面、清空整篇检查和导出。校对抛错时这段逻辑被跳过。
- `generatePages()` 约第 489 行仅凭旧页面的 `qa.pass` 就跳过重建。
- `accept()` 约第 641–649 行没有核实页面是否对应当前分镜内容。

### 最小修复要求

- 将新图成为当前分镜与下游失效处理放在同一个明确的状态更新边界；不能依赖后续校对成功才失效。
- 相关页面、整篇检查、验收状态和导出必须失效；原文件保留，不以删除文件代替状态管理。
- 继续制作和验收必须能够识别过期成稿。选择最小可靠实现，避免只给当前异常分支打补丁。
- 核对实际 artifact ID 命名：代码同时出现 `image:第1页-第1格` 与 `image:1-1` 等形式，不要假定依赖失效已经命中。
- 审查修订、重试、找回图片等更新当前分镜的入口，保持一致；是否受影响逐个验证，不扩展为无边界重构。

### 必须新增的回归

- 复现“新图保存成功 → QA 中断 → 重新校对 → 继续 → 验收”，证明不能导出旧页。
- 修复前先让正确行为断言失败，例如断言旧页不再是有效候选、验收会拒绝过期成稿；不要把错误现状写成预期。
- 验证旧图仍在磁盘，其他未受影响页面不会被无故重画。
- 覆盖实际受影响的其他挂接入口。

## 4. P1-02：跨方案版本恢复图片

### 触发与证据

旧版本存在待恢复 `pending` 时生成新版方案，旧任务仍留在当前作品记录中。新版确认后执行原图找回，旧版本图片被挂到新版分镜。

隔离复现用模拟方案和图片，在测试中设置确认状态来检验恢复边界，未进行真实方案确认或远端生成：

```text
NEW_PLAN_OLD_PENDING:
  version=2, pending=true, pendingPrompt=旧版图
RECOVER_OLD_IN_NEW_PLAN:
  version=2, attachedOldPanel=true, prompt=旧版图
```

### 原因与代码入口

- `planProject()` 约第 261–262 行切换方案并清空图片集合，却没有同步处理旧 `pending` 和关联任务状态。
- `generate()` 创建的 `pending` 没有完整的版本归属校验契约；请求记录虽有 `projectVersion`，恢复没有据此隔离。
- `recoverImage()` 约第 597–618 行校验的是当前方案获准状态，然后按图片 key 挂接，没有验证图片属于当前方案。

### 最小修复要求

- 待恢复任务绑定方案版本和必要的方案身份信息，恢复前验证归属。
- 换版时归档旧待恢复任务及关联状态，保留原图与证据；迟到结果不得挂进新版。
- 保证旧任务的失败状态不会让新版显示错误的重试入口。
- 老项目缺少字段时采取保守兼容策略：能从可信记录确定归属才恢复，无法确定时提示人工处理。不要猜成当前版本，也不要自动重生。

### 必须新增的回归

- v1 待恢复 → 修改为 v2 → 正常确认 v2 → 尝试找回 v1 图，不能挂入 v2。
- v1 图片在换版后迟到落盘，仍不能成为 v2 当前分镜。
- 同一版本的正常恢复继续可用。
- 缺少版本字段的旧记录不会被错误认领，原文件和历史记录保留。

## 5. P1-03：正式分镜质检失败后的人工出口缺失

### 触发与证据

正式分镜原图存在且 `qa.pass=false` 时，页面提示“采用当前图再继续”，但接口只支持样张的明确采用，没有正式分镜的同等决定。继续制作检查到该图就再次暂停。

隔离复现连续执行两次继续：两次均为 `status=attention`、`pages=0`、`modelCalls=0`，停在相同提示。没有自动重画是正确的，但没有完成用户所需的下一步。

### 原因与代码入口

- `generatePages()` 约第 499–509 行要求人工查看或采用，但没有落实采用状态。
- `server/server.mjs` 的 `previewDecisionInput()` / `preview-decision` 只处理样张。
- `app/page.tsx` 约第 2007–2025 行的 `reviewable` 只选择 `qa.pass===null` 的未完成校对记录，明确失败图片不显示重新检查入口。

### 最小修复要求

- 为正式分镜补齐明确的“采用当前图片”操作；用户需看见并确认相关问题。
- 决定绑定当前图片和作品版本，处理重复提交，拒绝对过期图片的决定。
- 人工采用与模型 QA 分开记录，不把 `qa.pass=false` 改成模型通过，不抹去问题。
- 用户采用后可以继续排版，仍需进行正常的页面与整篇验收；不要自动通过最终验收。
- 允许对明确失败的原图再次校对，且此操作不会重新生图。
- 没文件、损坏文件、结果未知的任务不能伪装成可采用图片。
- 沿用现有 UI 风格和确认机制，新增最小必要操作。

### 必须新增的回归

- 失败分镜经明确采用后可以继续，采用动作不会发起生图。
- 未采用仍暂停，不隐式接受，不自动重画。
- 重复操作不会重复执行，过期图片决定被拒绝。
- 失败图片重新校对只运行 QA。
- 样张原有确认、恢复和最终验收要求不被破坏。
