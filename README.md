# 温蒂创作室

温蒂创作室是一个只在本机运行的漫画创作台。你在网页里写下故事、确认方案、查看样张、修改画面并保存成品；作品、设定和素材始终保留在本机目录中。

它适合已经有温蒂世界观、人物参考和固定工作指引，希望把每次漫画创作收拢到一个清晰流程里的创作者。

## 开始使用

在 Finder 中双击上一级文件夹的 **打开温蒂创作室.app**。浏览器会打开：

<http://127.0.0.1:4318>

如果你从工程目录启动：

```bash
npm run server
```

打开网页后，按这个顺序创作：

1. 写下故事想法，选择页数、模型、思考力度和制作方式。
2. 查看逐页方案。需要调整时直接写修改意见；满意后确认方案。
3. 查看人物与主场景样张。样张用于尽早确认人物、服装和场景方向。
4. 点击继续制作，等待逐页绘制、排版和校对完成。
5. 在“漫画与成品”中放大检查全部页面，勾选验收项后收下整套成品。

网页关闭不会删除已完成的内容。重新打开创作室后，可以从上次保存的节点继续。

## 样张、重试与创作额度

样张检查发现问题时，会保留原图并等待你选择采用或修改，不会自动重画。两张样张都通过检查或由你明确采用后，再点击 **继续制作** 进入整篇制作。已知问题会留在作品记录中，之后仍可局部修改。

正式分镜的画面质检如果没有通过，创作室会保留原图和模型质检结论，并显示 **采用当前图片** 或 **修改这一张**。采用只是你的人工决定，不会把模型失败改写成通过，也不会跳过页面和整篇校对；重新检查原图只运行画面校对，不重新生图。

如果分镜填写了手机或车机内屏文字，后期排字会另存一张后期图，原始分镜仍保留。页面排版、继续制作和最终验收都以这张实际采用的后期图为依赖；暂停后再次继续不会因为已完成内屏排字而重复处理。

点击 **采用当前图片** 前，创作室会在本机确认当前记录的文件仍在作品目录内、能解码并与已保存的完整性记录一致。文件缺失、损坏或被替换时，采用会被拒绝；模型质检和任务证据会保留，也不会留下成功的重复提交记录。若作品在检查期间更新，请刷新作品后重新查看再操作。

网页顶部显示当前账号实际读取到的 5 小时和 1 周额度。5 小时额度低于 10% 时，创作室会保存节点、暂停新的生图，并提示你在额度重置后继续。

额度接口返回空值、未知值或读取失败时会显示“暂不可用”；如果显示的是上一次成功读取的额度，页面会标注观测时间，不把它当作实时额度或已验证的保护阈值。

如果页面提示“上次生图可能已经完成，但原图还没有保存进作品”，先点 **检查已有原图**，找回已经保存的图片。重新校对原图不会重新生图，但模型校对仍会使用账号额度。如果无法确定上次是否产出，先保留记录；明确选择重试时，只重新生成当前这一张，可能产生额外的图片请求。

网页生图后台会把每次单图请求写入隔离的执行清单，并按 **等待后台接单 → 后台已接单 → 已准备提交 → 已提交生成 → 原图已保存** 显示真实阶段。`codex queue` 返回成功只代表消息已排队，不代表后台已经开始处理；只有清单中的同一 `requestId` 写入接单证据后才会进入下一阶段。接单等待超时会停止本机等待、保留请求和找回入口，不会自动重排队或把未知结果当成无图。

如果页面显示后台尚未确认接单，请先查看当前请求记录和网页后台状态，不要反复点击继续制作。历史会话文件或旧的后台配置不能单独证明当前后台就绪；真实网页接单、提交和下载仍需在隔离、明确授权的实机验收中确认。

侧栏的 **刷新已保存网页生图后台状态** 只重新读取本机状态，不会执行新探针、发送消息、唤醒旧任务或重新生图。只有与当前配置完全匹配的 `threadId`/`hostId`、且仍在有效时间内的隔离就绪记录（`.runtime/chatgpt-web-worker-probe-result.json` 中包含 `schemaVersion`、身份、`ok`、IAB 可用、已登录、输入框可用和 `checkedAt`）才会显示“已通过最近的隔离就绪检查”；记录缺失、过期、未来时间、失败或属于其他宿主时会保持待核验。当前安装 CLI 没有受支持的本机新探针执行入口；需要重新确认时，应使用没有旧生图积压的隔离后台完成无生图探针，再由该后台实际写入对应身份的结果。

如果请求清单后来已经写入与当前任务一致的 `accepted=true`，但随后进入 `failed`（例如提交前 `IAB_UNAVAILABLE`），页面会优先显示这条已核对身份的终态，不再把旧的 `not_accepted/queued` 当作当前状态。系统只在读取同一请求目录、作品和方案版本的证据后才这样覆盖公开投影；请求、原图和 `pending` 仍保留，结果未知时不会改写成“确认无图”。

修改逐页方案后，旧方案的待恢复任务会归档到历史记录，迟到的旧图不会挂接到新方案。只有能确认作品和方案版本归属的记录才会恢复；老记录缺少可信版本信息时会保留原图并提示人工处理，不会猜成当前版本，也不会自动重生。

## 人物、世界观与素材

“人物与世界”分成两部分：

- **文字设定**：世界观、工作指引、技术附录和专题规则可以查看、智能生成修订建议，并在确认后保存。保存前会保留旧版本。
- **图片素材**：人物与服装、场景与物品分开整理。你可以手动加入图片，也可以从作品中提炼素材。系统只给出是否适合长期复用的建议，真正加入素材库、补充世界观或工作指引仍由你确认。

默认情况下，小林不会出场或被暗示；只有在创建故事时明确允许，才会进入本篇参考范围。

## 作品保存在哪里

每篇创作保存在：

```text
作品/<作品编号>/v<方案版本>/
```

其中会保留方案、参考快照、样张、原始分镜、局部修订、成稿和验收记录。验收完成后的页面位于 `成品/`，并会同时生成整套 ZIP 包。

“我的作品”按作品展示。打开某一篇后，才会看到该作品的每一页。删除已完成作品时需要输入完整标题确认，删除内容会先移入本地废纸篓。

## 本机运行与账号边界

创作室通过本机 Codex 生成方案和检查画面，通过 Codex 内嵌浏览器中的 ChatGPT 网页生成图片。创作内容及所需参考图会发送至相应服务；创作室不会复制登录凭据、读取浏览器 Cookie，也不会把账号令牌转交给自建服务。

首次使用前，请确认 Codex 已在这台电脑登录，内嵌浏览器中的 ChatGPT 可用，且网页生图后台已经初始化。若网页显示“创作连接需要查看”，先检查登录状态；如果提示后台尚未初始化或记录已失效，需要先恢复后台连接，反复点击生成不会解决问题。

本服务只监听本机地址，不能从其他设备直接访问。

## 从源码安装

需要 macOS、Node.js 22.13 或更高版本、已登录的 Codex，以及可用的本机 Python 与 Pillow。

```bash
npm ci
npm run build
npm run server
```

常用命令：

```bash
npm test       # 回归测试
npm run lint  # 静态检查
npm run build  # 生成网页文件
npm run server # 启动本地创作室
```

`作品/`、`.runtime/`、依赖目录和构建产物默认不会纳入 Git；代码、设定和测试可以正常版本管理。

## 源码结构

- `app/`：创作页面和样式，使用 React、原生控件和普通 CSS。
- `server/`：本机接口、创作流程、图片后台连接、排版和素材管理。
- `launch.mjs`：本机启动入口。
- `设定/`：世界观、创作指引和参考素材。
- `tests/`：使用隔离目录和模拟生成结果的回归测试。

工程已移除未使用的通用 UI 组件库、组件生成器配置及其专用依赖。界面修改从 `app/page.tsx` 和 `app/globals.css` 开始；只有实际功能需要时再引入组件或依赖。

本地回归测试验证流程、恢复逻辑和文件保护，不代表真实远端生图已经验收。
