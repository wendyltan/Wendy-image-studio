# 温蒂创作室

温蒂创作室是一个只在本机运行的漫画创作台。你在网页里写下故事、确认方案、查看样张、修改画面并保存成品；作品、设定和素材始终保留在本机目录中。

它适合已经有温蒂世界观、人物参考和固定工作指引，希望把每次漫画创作收拢到一个清晰流程里的创作者。

## 开始使用

在 Finder 中双击上一级文件夹的 **打开温蒂创作室.app**。浏览器会打开：

<http://127.0.0.1:4318>

如果你从工程目录启动：

```bash
npm run server
```

网页右上角的 **重启创作室** 会先确认没有正在执行的制作任务，再调用与 App 入口相同的安全替换流程；新后台健康检查通过后页面会自动刷新。重启只重载服务，不会自动继续作品或重新生图。

打开网页后，按这个顺序创作：

1. 写下故事想法，选择页数、模型、思考力度和制作方式。
2. 查看逐页方案。需要调整时直接写修改意见；满意后确认方案。
3. 查看人物与主场景样张。样张用于尽早确认人物、服装和场景方向。
4. 点击继续制作，等待逐页绘制、排版和校对完成。
5. 在“漫画与成品”中放大检查全部页面，勾选验收项后收下整套成品。

网页关闭不会删除已完成的内容。重新打开创作室后，可以从上次保存的节点继续。

## 样张、重试与创作额度

样张检查发现问题时，会保留原图并等待你选择采用或修改，不会自动重画。两张样张都通过检查或由你明确采用后，再点击 **继续制作** 进入整篇制作。已知问题会留在作品记录中，之后仍可局部修改。

正式分镜的画面质检如果没有通过，创作室会保留原图和模型质检结论，并显示 **采用当前图片** 或 **修改这一张**。采用只是你的人工决定，不会把模型失败改写成通过，也不会跳过页面和整篇校对；重新检查原图只运行画面校对，不重新生图。

局部修改会把本次说明单独记录为“修改差异”，与冻结的原始分镜提示词和你选定的编辑基图一起提交，并明确要求其余内容保持不变。连续失败时，下一次不会自动把所有失败稿串成新的基图；若你没有另选基图，系统会回到这一路径中最近一次稳定的已选基图。只改文字、文字框或排版的问题会引导到本地排版修复，不消耗新的生图请求。

成稿质检如果只发现文字遮挡或排字问题，状态栏和对应页面会显示 **修复本页排版**，并暂时隐藏普通的“继续制作”。修复只调整本地文字框位置并重新校对，不会重新生成原始分镜。已有两页以上成稿时，还可以点击 **统一已有页面排版**，把旧页面重新组合为当前统一的圆角分格、浮动文字框和页码样式；旧成稿仍保留在制作记录中。

如果分镜填写了手机、电脑或车机内屏文字，后期只用一次低思考视觉定位取得玻璃四角，随后由本地排版器逐字绘制和透视融合，不再让远端模型现场编写排版脚本。后期图会另存，原始分镜仍保留；暂停后再次继续不会重复处理已经完成的内屏。

点击 **采用当前图片** 前，创作室会在本机确认当前记录的文件仍在作品目录内、能解码并与已保存的完整性记录一致。文件缺失、损坏或被替换时，采用会被拒绝；模型质检和任务证据会保留，也不会留下成功的重复提交记录。若作品在检查期间更新，请刷新作品后重新查看再操作。

网页顶部显示当前账号实际读取到的 5 小时和 1 周额度。每个制作小阶段结束后会自动重新读取，并显示观测时间；5 小时额度低于 10% 时，创作室会保存节点、暂停新的生图，并提示你在额度重置后继续。

额度接口返回空值、未知值或读取失败时会显示“暂不可用”；如果显示的是上一次成功读取的额度，页面会标注观测时间，不把它当作实时额度或已验证的保护阈值。

如果页面提示“上次生图可能已经完成，但原图还没有保存进作品”，先点 **检查已有原图**，找回已经保存的图片。重新校对原图不会重新生图，但模型校对仍会使用账号额度。如果无法确定上次是否产出，先保留记录；明确选择重试时，只重新生成当前这一张，可能产生额外的图片请求。

生图由软件直接启动一次 Codex 执行，生产传输标记为 `direct-chrome`，不使用 Codex 内嵌浏览器 IAB。Chrome extension 的公开 `createBrowserTab` 不支持隐藏参数，因此不会传入 `visible`；创建专用标签页时 Chrome 可能短暂取得焦点。后续 Playwright 操作只绑定本次新建的 **🎨 温蒂生图** `sessionName` 标签页，完成或失败后关闭；不会接管、导航或写入已有的温蒂创作室标签页。上传前只在运行目录生成适合网页传输的轻量副本，固定素材原文件不会被改动。

浏览器执行器只负责已经冻结的上传、发送、等待和下载，固定使用当前创作模型的低思考力度；故事方案仍使用你选择的创作模型和思考力度，画面校对单独记录为 QA。作品记录会分别保存 creative、browser-executor、QA 的模型、思考力度和阶段耗时，方便判断本地准备、网页等待或校对占时。

当前公开 Computer Use API 只有浏览器/标签页读取与创建入口，没有窗口或标签页 active/focused 更新、恢复或校验接口，也没有可验证的后台 Playwright 能力。因此软件无法严格保证零焦点切换，也不会伪称后台隐藏或焦点已经恢复；已知边界会记录在执行清单中。若 Chrome 自身报告焦点或浏览器能力错误，当前请求会在上传和发送前停止并保留单图重试入口，不会退回 IAB。整个流程不使用坐标、系统鼠标、系统键盘或脆弱快捷键。

每次请求保留独立身份和执行记录。发送前先记录提交意图，任何发送中断均保留为未知，不自动重发。登录失败直接提示登录；执行退出后没有原图则停止并保留恢复入口，不再无限等待“后台接单”。原图须通过本地解码和完整性检查才挂接作品。


修改逐页方案后，旧方案的待恢复任务会归档到历史记录，迟到的旧图不会挂接到新方案。只有能确认作品和方案版本归属的记录才会恢复；老记录缺少可信版本信息时会保留原图并提示人工处理，不会猜成当前版本，也不会自动重生。

## 人物、世界观与素材

“人物与世界”分成两部分：

- **文字设定**：世界观、工作指引、技术附录和专题规则可以查看、智能生成修订建议，并在确认后保存。保存前会保留旧版本。
- **图片素材**：人物与服装、场景与物品分开整理。你可以手动加入图片，也可以从作品中提炼素材。系统只给出是否适合长期复用的建议，真正加入素材库、补充世界观或工作指引仍由你确认。

默认情况下，小林不会出场或被暗示；只有在创建故事时明确允许，才会进入本篇参考范围。

## 作品保存在哪里

每篇创作保存在：

```text
作品/<作品编号>/v<方案版本>/
```

其中会保留方案、参考快照、样张、原始分镜、局部修订、成稿和验收记录。验收完成后的页面位于 `成品/`，并会同时生成整套 ZIP 包。

“我的作品”按作品展示。打开某一篇后，才会看到该作品的每一页。删除已完成作品时需要输入完整标题确认，删除内容会先移入本地废纸篓。

## 本机运行与账号边界

创作室通过本机 Codex 生成方案和检查画面；图片生产主路径标记为 `direct-chrome`，通过一次性新建的专用 Chrome 标签页中的 ChatGPT 网页生成图片。创建时可能短暂切换 Chrome 焦点，后续只操作本次任务自有标签页，完成或失败后关闭。创作内容及所需参考图会发送至相应服务；创作室不会复制登录凭据、读取浏览器 Cookie，也不会把账号令牌转交给自建服务。

首次使用前，请确认 Codex 已登录、额度可用、Chrome Computer Use 扩展已连接、当前正在查看温蒂创作室标签页，且 ChatGPT 网页已登录。创建专用标签页时可能短暂取得焦点，但不会修改工作室标签页内容；登录失败、额度不足和连接中断会显示具体原因，发送状态不明时保留记录且不会自动重试。反复点击生成不能绕过这些条件。

本服务只监听本机地址，不能从其他设备直接访问。

## 从源码安装

需要 macOS、Node.js 22.13 或更高版本、已登录的 Codex，以及可用的本机 Python 与 Pillow。

```bash
npm ci
npm run build
npm run server
```

常用命令：

```bash
npm test       # 回归测试
npm run lint  # 静态检查
npm run build  # 生成网页文件
npm run server # 启动本地创作室
```

`作品/`、`.runtime/`、依赖目录和构建产物默认不会纳入 Git；历史排障或 bug 修复 Markdown 放在 `docs/` 时不会进入后续提交，`docs/` 里的其他类型文件以及代码、设定和测试仍可正常版本管理。

## 源码结构

- `app/`：创作页面和样式，使用 React、原生控件和普通 CSS。
- `server/`：本机接口、创作流程、图片后台连接、排版和素材管理。
- `launch.mjs`：本机启动入口。
- `设定/`：世界观、创作指引和参考素材。
- `tests/`：使用隔离目录和模拟生成结果的回归测试。

工程已移除未使用的通用 UI 组件库、组件生成器配置及其专用依赖。界面修改从 `app/page.tsx` 和 `app/globals.css` 开始；只有实际功能需要时再引入组件或依赖。

本地回归测试验证流程、恢复逻辑和文件保护，不代表真实远端生图已经验收。
